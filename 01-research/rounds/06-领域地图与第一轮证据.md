# 领域地图与第一轮证据

状态：第一轮原始来源扫描；截至 2026-10-20。此文是研究入口，不是最终趋势结论。

## 研究对象和证据层级

- **IP / 架构发布**：证明设计公开及目标能力，不证明某款手机已量产、实际能耗或用户体验。
- **SoC / 手机发布**：证明产品配置和厂商描述，不自动证明跨平台性能优势。
- **独立测量**：需核对设备、系统、功耗模式、工作负载、运行时间和可复现性。
- **行业趋势**：需要跨多个代际、多个独立来源及替代解释检查。

## 待检验的跨代假设

1. **异构化持续深化**：从不同 CPU 核，到 CPU/GPU/NPU 按工作负载分工。反例是全大核等不同取舍；需要比较长期负载和热约束。
2. **数据搬运愈发重要**：NPU 共享存储、GPU 缓存和 SoC 互连可能比峰值算力更能解释实际收益。需要源级机制和任务级测量验证。
3. **专用能力与通用能力并进**：GPU 光追硬件、NPU 张量单元与 CPU 矩阵扩展并行发展。需核对软件栈和真实负载覆盖，避免把功能存在等同于实用收益。
4. **指标向端到端转移**：峰值算力之外，任务时延、持续性能和能耗可能更贴近用户价值。需查找统一基准与独立设备测试。

这些是分析推断和取证任务，不是已完成的行业结论。

## 下一轮最小取证任务

1. 补齐 2007—2010 与 2014—2015 的 CPU/GPU 产品节点，避免时间轴前段空白。
2. 查 Arm、Qualcomm、Apple、MediaTek 的原始技术文档和会议材料，重建机制变化；补 Samsung/HiSilicon 等不同路线。
3. 选取可复现的 CPU、GPU、NPU 终端基准，建立同口径比较规则和负面证据清单。
4. 对 big.LITTLE 与全大核、GPU 光追与热预算、NPU 专用化与 CPU/GPU 替代路线做三组深读比较。

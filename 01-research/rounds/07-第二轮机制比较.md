状态：截至 2026-10-20 的公开资料研究。此轮建立机制与边界，尚无跨设备、同口径的独立性能结论。

## 二、CPU：big.LITTLE 与全大核

### 共同问题

有限的手机功耗与热预算中，同时满足短时响应、持续多线程和轻载待机。

### 两种机制

- Samsung 对 Exynos 5 Octa 的 2013 年说明强调 Cortex-A15 和 A7 的不同工作点，以及软件调度任务到不同核心的重要性。其后的 HMP 方案允许所有物理核心同时使用。[R05][R07]
- MediaTek 2024 年白皮书以自家 Dimensity 1200/9000/9200/9300 为例，主张较新的中档乱序核心在相关性能区间内可替代小型顺序核心，并称简化了集群与调度。[R08，第 3.2 节，图 3.1–3.2]

### 第一轮判断

**[OBSERVATION]** 移动 CPU 的异构设计不是固定的“大核加小核”配方；核心自身的能效曲线、任务分布、软件调度与实现技术会改变最佳组合。2013 年的 Samsung 路线和 2023 年的 MediaTek 产品共同支持“存在不同设计取舍”，但不支持“全大核普遍更优”。

**证据边界：** MediaTek 的白皮书同时改变了 IP 代际、制程和实现方法。其功耗曲线是厂商测量，不能把跨代差异精确归因于取消小核。[R08，第 4.1–4.2 节]

**下一步判别：** 在同一设备或足够接近的平台上比较轻载、交互突发、持续多线程和长时间游戏；记录频率、核心驻留、温度、整机功耗和调度策略。公开资料中若缺同口径样本，则只给有条件判断。

## 三、GPU：硬件光追代表什么

Arm 对 Immortalis-G715 的开发说明确认硬件 ray tracing、Vulkan ray query 与完整 pipeline 支持；同时指出早期驱动可能只暴露 ray query，并建议移动端先采用 ray query。完整 pipeline 会失去某些 framebuffer compression 优势，光线方向分歧、BVH 结构也影响性能。[R09，Ray tracing 与 best practices]

**[INFERENCE]** 移动 GPU 的演进不是单纯加一个光追单元；硬件、驱动、渲染路径和内容必须共同适配功耗预算。光追支持证明能力存在，不能直接推出长期稳定帧率、广泛游戏采用或整机能效收益。

**下一步判别：** 找使用 ray query 与完整 pipeline 的公开游戏/技术演示，保留分辨率、画质、帧率曲线、功耗和热稳定时间；寻找同 SoC 的光追开/关对照。Arm 的 IP 级加速宣称只在相同测试范围内引用。

## 四、NPU：专用硬件与实际执行路径

Qualcomm 的 2015 年 Hexagon 680 资料显示，影像与视觉任务曾通过 DSP/HVX/ISP 协同加速。[R06] 后来的 Hexagon 公开技术回顾记录了张量单元和共享存储的发展。[R02] 这支持从 DSP 向 AI 专用计算演进的产品脉络。

Android 的 NNAPI 文档说明，模型分区、驱动编译或执行失败时，某些算子或整模型可能退回 CPU 执行。[R10，Error management and CPU fallback] 因此“手机含 NPU”和“该模型主要运行在 NPU”是不同命题。

MLCommons Mobile 将单流任务指标定义为延迟，并公开模型、质量目标、系统与加速器元数据，以及功耗测量字段。[R11，Scenarios & Metrics / Benchmark Results] 这是下一轮比较模型任务的合适入口；具体提交结果还需逐条检查，不能把不同版本或模型混合排名。

**[INFERENCE]** NPU 的有效收益由算子覆盖、精度、编译器、模型分区、内存搬运和热约束共同决定。峰值 TOPS 只能作为硬件规格的一部分。

**下一步判别：** 对图像、语音和生成式模型各选一个公开工作负载，收集算子/精度支持、实际执行单元、首 token 或单次任务延迟、能耗、质量与内存占用。比较 CPU/GPU/NPU 的最强可行执行路径，而不是理论峰值。

## 五、需要继续查证的问题

1. 2010—2016 年间，Mali/Adreno 的通用计算能力在真实手机任务上如何使用？
2. 2013 年 big.LITTLE 的发布、量产和软件调度成熟时间如何分列？
3. 全大核在轻载及热稳定状态下的结果能否找到独立且同口径的来源？
4. 移动光追从 IP 能力到真实游戏采用和持续体验，中间隔着哪些驱动及内容条件？
5. 不同端侧 AI 软件栈中，何时发生 CPU fallback、部分分区和数据拷贝？

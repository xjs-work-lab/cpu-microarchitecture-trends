# 移动 CPU 微架构历史因果链完整性审计 v0.1

**日期：** 2026-10-23  
**审计对象：** 2007–2026 移动 CPU 微架构历史时间线、核内机制矩阵、LLVM 23.1.4 软件利用路径  
**审计目的：** 判断历史叙述是否从“发生了什么”推进到“为什么发生、带来什么、瓶颈转移到哪里”，而不是提前制作 PPT。  
**资料限制：** PUBLIC_ONLY；无真机、无私有高校/厂商访谈；本审计不生成性能测量。

## 一、审计结论

**结论：主线已建立，但还不够支撑“所有代际都解释清楚”的最终结论。**

目前较完整的因果链集中在 Arm Cortex-A72、A76、A77/A78 的公开微架构说明，以及部分 Apple/Samsung 的公开论文或第三方逆向分析。对较早的 A9/A7，能够说明路线转折，但机制细节/量化证据深度不一致；对近年 Cortex-X、Arm C1/C2、Qualcomm Oryon、HiSilicon Taishan 等路线，产品化与方向信息较充分，但逐核内部机制与独立收益证据明显不均衡。

LLVM 23.1.4 审计补上了“编译器是否存在利用入口”这一层，但不能替代目标手机实际生成代码、设备工作负载和能耗测量。因此，现阶段应称为**证据约束下的历史解释框架**，而不是完整的因果证明。

## 二、统一审计准则

每条演进记录至少要区分下列五个环节：

1. **观察到的约束/前一代瓶颈**：有来源的工作负载、功耗/面积/热约束或明确的前代限制。
2. **设计动作**：某结构、流水线、ISA、缓存/互连或核心组合发生什么变化。
3. **作用机制**：该变化如何改变供给、并行度、依赖延迟、数据移动或活动功耗。
4. **收益与代价**：公开证据支持的收益；以及面积、功耗、复杂度、验证或软件成本。
5. **后续瓶颈/下一代响应**：该动作解决/缓解了什么，又可能把限制转移到哪里；需标明这是公开陈述还是分析推论。

证据强度分级：
- **A — 设计者明确说明动机**：原始设计者/厂商明确写出目标或约束；不自动证明收益因果。
- **B — 多来源相互支持**：官方机制事实与独立研究/同期负载证据相互支持。
- **C — 机制合理但主要为分析推论**：机制关系成立，但缺少明确设计动机或独立验证。
- **D — 证据不足/未知**：不得写成事实；保留未知。

## 四、因果链中最重要的修正

### 1. “瓶颈转移”必须标为推论，除非有直接证据
例如：更宽前端可能使后端执行资源或数据供给成为新的限制；更大乱序窗口可能让内存带宽、依赖链和错误预取成本更突出。这些是机制上合理的解释，但如果没有设计者原话或针对性测量，不能写成某代厂商“因此”设计下一代结构的既定原因。推荐措辞：
- 事实：某代增加了 X。
- 直接动机：来源明确写出的目标 Y。
- 分析推论：X 有助于缓解 Y；在某些负载下可能把瓶颈转向 Z。
- 未知：没有证据证明下一代的 Z 变化就是由此导致。

### 2. 性能数字不得反向推导隐藏微架构
不能从 IPC、Geekbench、峰值频率或能效分数推断 ROB、LSQ、物理寄存器数、分支预测器表结构或执行端口数量。第三方逆向可以纳入，但需保留其方法、日期、置信区间/测量边界。

### 3. 硬件规格、LLVM 模型和设备表现是三个不同层次
- 硬件规格：厂商/可信逆向描述真实结构。
- LLVM 模型：编译器对指令延迟、资源与 tuning 的抽象；模型可能共享、经验拟合或使用乐观值。
- 设备表现：具体 SoC、系统软件、编译参数、工作负载、功耗策略、温度和散热共同决定。
不能用其中任意一层替代另外两层。

### 4. SoC 级变化不能全部归因于 CPU 核
异构核心组合、缓存/互连、DRAM、NPU/GPU、封装、制程、电源管理和手机散热都会影响结果。跨产品比较若未控制这些因素，只能说明系统级变化，不能宣称 CPU 核单因素因果。

## 五、下一阶段的研究优先级

按“补齐因果链价值/公开证据可得性”排序：

1. **优先补齐 A72→A76→A77/A78 的阶段间因果连续性。** 这条主线公开结构资料最丰富；逐项核对上一代已知约束、下一代明确动机与新增机制，避免把相邻代变化机械连成因果。
2. **独立复核 Apple Cyclone/Firestorm、Samsung M1–M5 的第三方/论文证据。** 特别标记逆向测量方法、仿真频率/trace、真实芯片与模型的区别。
3. **补齐近年路线的公开机制而非只补产品名。** Arm X/C1/C2、Oryon、Taishan 只有在找到原始结构证据时才增加细节；否则保留未知。
4. **逐条对齐 LLVM 入口。** 每个机制注明 direct feature / scheduler-model / profile / indirect only / not observable，且不声称软件路径已在手机实际启用。
5. **最后审计 SoC 层面的混杂变量。** 在结论里区分核内性能、SoC 平台表现与手机持续性能。

## 六、本次审计决定

- 不把当前历史时间线标成“因果链全部完成”。
- 不扩充未有可靠来源支持的 ROB/LSQ/物理寄存器/预测器数值。
- 以 A72/A76/A77/A78 为第一条连续因果主线，其他厂商采用平行对照和证据等级表达。
- 后续更新应同时写回历史时间线与机制矩阵，审计文档只记录跨文档的判断、缺口和修正原则。
- 暂停 PPT 制作，直到历史因果链审计收敛。

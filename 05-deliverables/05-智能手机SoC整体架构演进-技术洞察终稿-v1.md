# 智能手机 SoC 整体架构演进：技术洞察终稿 v1.0

**资料截点：2026-10-20｜研究模式：PUBLIC_ONLY｜版本：v1.0（研究终稿初版，待技术专家评审）**

> **核心结论**
>
> 2007—2026 年智能手机 SoC 的长期变化，不是 CPU、GPU、NPU 各自持续变大，而是随着负载和产品目标改变，重新安排计算单元、数据路径、软件执行路径、通信物理边界及功耗/热预算。近年的重要信号是 AI 能力向 CPU、GPU、NPU 等多个执行域扩散，同时缓存、外存、软件运行时、封装和终端散热的重要性上升。
>
> 这支持一个**系统级设计方向**，但不证明“共享缓存是所有任务的首要瓶颈”，也不证明某种芯片路线普遍领先。公开证据能支持阶段性结构事实和有条件的趋势判断；多数跨代收益仍不能从制程、频率、内存、软件和终端热设计中单独拆分。

本文将前九轮研究收敛为五个最终研究问题的逐项回答。它不是厂商规格全集，也不是产品排名；引用编号均指向原始来源或来源卡。所有“未披露”均表示本次所核公开资料未提供证据，不代表能力不存在。

## 0. 给技术评审者的摘要

### 0.1 六条最重要的判断

1. **[OBSERVATION] 任务驱动的异构分工持续深化。** 固定功能流水线、可编程 DSP、低功耗感知域、GPU 计算、NPU 和 CPU 矩阵扩展并存。新增专用单元没有让通用单元退出；“所有 AI 都会迁到 NPU”不符合公开产品方向。[P03][P04][P08][E08][E10][V13]
2. **[OBSERVATION] 物理集成度不是单调增长。** Snapdragon S4 的 LTE 基带/AP 集成，与 Snapdragon 865 平台搭配 X55 Modem-RF 的方案形成反例；Exynos 2200 又公开披露集成 5G 基带。制程、射频频段、面积、供应链和产品策略可能共同影响边界，现有资料不能单独解释厂商选择原因。[E02][E05][P07][P10]
3. **[OBSERVATION] 同一个用户功能跨越多个层次。** 视频拍摄涉及传感器、ISP、DSP/NPU、编码器、内存和相机软件；游戏涉及 CPU 提交、GPU 渲染、缓存/DRAM、显示合成、帧同步和热反馈；通信还涉及协议状态、RF、天线与网络条件。只看一个 IP 指标容易漏掉系统瓶颈。[V01–V08][N01–N08][G01–G09]
4. **[FACT/设备级] 峰值指标和持续体验必须分开。** 同为 Dimensity 9500 的 OPPO Find X9 与 vivo X300，在 Notebookcheck 报告的 3DMark Wild Life Extreme Stress Test 稳定性分别为 74.3% 和 46.7%。这是两台成品手机的测试结果，不是 GPU 绝对性能、功耗或微架构因果差异；两者来自同一评测机构，亦非跨机构复验。[X07][X08][X09]
5. **[OBSERVATION] 数据局部性是有条件的重要机制，不是跨任务的万能答案。** 动态共享缓存、SLC、GPU tile memory、低精度、内存压缩和跨引擎直连都有公开结构信号；但没有足够的公开逐任务带宽/功耗测量，证明它们对所有负载都是第一瓶颈。通信尤其不能被简单归结为共享缓存问题。[E08][E09][V06][V13][V14][N01–N08]
6. **[HYPOTHESIS] 2027—2028 年更值得跟踪的是系统级 QoS 与数据/功耗治理。** CPU/GPU/NPU 多域执行、内存与缓存管理、常驻低功耗路径、无线协议节能及持续游戏热反馈值得持续观察；方向可信度高于具体收益幅度。不能预测未发布芯片的具体配置或赢家。[E08–E11][V13][V14]

### 0.2 本报告能回答什么、不能回答什么

- **可以回答：** 五个历史阶段的代表性结构变化；模块职责为何随负载变化；代表平台的不同取舍；四类任务的系统路径和指标；2027—2028 有条件方向及证伪条件。
- **不能据公开资料准确回答：** 某个架构改动单独贡献多少 IPC、帧率、token/s 或续航；任一手机各功耗域的精确瓦数；未公开的 NoC 拓扑、缓存命中率和片上真实连线；跨厂商在同制程、同软件、同终端条件下的绝对胜负。
- **结题判断：** 适合进入内部技术评审并作为 PPT 内容母稿；涉及定量架构因果的部分仍需标为未知，而非包装成确定结论。

## 1. 研究目标、范围与证据规则

### 1.1 唯一主问题

解释 2007—2026 年智能手机 SoC 及其终端平台如何随交互、网页/媒体、摄影视频、游戏、蜂窝连接和端侧 AI 的变化，调整 CPU、GPU、DSP/NPU、ISP/编解码、显示、基带/RF、缓存/内存/互连、安全、软件与电热设计的职责；说明各机制的收益、代价和适用边界；据此对 2027—2028 年作有条件前瞻。

对象是**智能手机整体 SoC/平台**，而不只是 CPU。平板只在架构可比时作为辅助。PC/服务器技术不单独展开，除非用于解释移动端来源或差异。

### 1.2 证据标签

| 标签 | 定义 | 写作规则 |
|---|---|---|
| **[FACT]** | 原始文档直接披露的产品结构、接口、测量或方法 | 必须说明对象和资料层级；发布不等于量产 |
| **[CLAIM]** | 厂商/论文作者对收益或意义的主张 | 明确归属于来源；没有独立复现不当成事实收益 |
| **[OBSERVATION]** | 多个来源间可归纳的共同现象 | 不表示所有产品或任务都成立 |

| **[HYPOTHESIS]** | 需要后续数据检验的方向或机制 | 同时写出证伪条件 |
| **[UNKNOWN]** | 当前公开资料无法识别或未完成核实 | 不推断为不存在，也不以常识补造芯片细节 |

### 1.3 证据优先级与比较口径

本报告优先使用原始产品/IP文档、官方开发文档、论文/会议记录、公开基准方法和独立终端测量。机构声望或厂商规模不替代证据质量。每条量化结果应同时保留：

- 对象：裸片、配套芯片、平台、主板或整机；
- 设备、SoC、OS/驱动、基准/应用版本；
- 工作负载、质量设置、持续时间与基线；
- 指标与单位：延迟、吞吐、FPS、帧时间、瓦、焦耳/任务、温度或稳定性；
- 热环境、屏幕/网络等状态，以及尚未控制的变量；
- 来源是否独立、是否为同团队重复发布、是否可重现。

不同口径不拼成一个综合排名。CPU IPC、GPU FLOPS、NPU TOPS、手机续航和 3DMark 稳定性不是可互换的尺度。

## 2. 全 SoC 观察框架：从用户任务到可见结果

### 2.1 分析框架

用户任务与 QoS 目标  
→ 需要哪些计算、感知、通信和媒体功能  
→ 这些功能在哪些执行单元运行  
→ 中间数据经过哪些缓冲、缓存、DRAM、互连和软件接口  
→ 任务调度、频率/电源域、无线协议和热管理如何控制资源  
→ 最终呈现为延迟、吞吐、帧节奏、画质、可靠性、能耗与持续表现。

该框架是**功能级分析图**，不是某款芯片的物理连线图。实际产品的 ISP→NPU 路径、AP↔Modem 接口、缓存一致性和电源域，只有在原始资料明确披露时才能画成确定结构。

### 2.2 六个必须一起看的系统层

| 层次 | 典型组成 | 主要问题 | 公开证据常见边界 |
|---|---|---|---|
| 工作负载与 QoS | 交互、相机/视频、游戏、推理、无线通信 | 截止期、尾延迟、画质/模型质量、持续时间 | 产品发布常只给功能或峰值数字 |
| 计算/媒体引擎 | CPU、GPU、DSP、NPU、ISP、编解码、显示 | 哪类任务适合固定功能、可编程或矩阵执行 | IP 存在不证明应用实际使用 |
| 数据底座 | L1/L2/系统缓存/SLC、DRAM、UFS、互连、压缩、QoS | 数据移动、带宽争用、容量、局部性 | NoC 拓扑、逐任务流量和命中率多未披露 |
| 控制与软件 | OS、驱动、编译器、运行时、HAL、图形/AI API、调度 | 硬件是否可被软件调用，是否分区/fallback | API 能力不证明某机型实际执行路径 |
| 通信与常驻域 | Modem/baseband、RF、天线、Wi-Fi/GNSS、Sensor Hub | 无线状态、弱信号、唤醒、常驻监听与静态功耗 | 终端网络状态难统一，RF 与 AP 功耗边界不同 |
| 物理实现与保护 | 制程、频率、电源域、供电、封装、均热/散热、安全域 | 峰值/持续功率、可靠性、隐私、安全隔离 | 整机结果通常不能只归因于芯片微架构 |

## 3. 2007—2026：五个历史阶段与架构转折

> 下列阶段是用于解释代表性结构变化的**分析分期**，不是整个市场在某一年同时转型的统计结论。早期与中低端产品的公开结构覆盖较弱，因此阶段图以能说明机制的代表节点为主。

### 阶段一：2007—2012｜集成移动计算平台与连接压力

**阶段问题：** 智能手机需要在有限电池、面积和散热预算下处理蜂窝连接、应用、网页、媒体和图形。蜂窝代际升级会引入基带、RF、射频前端与天线的系统约束。

**结构响应。** Snapdragon 早期平台把 CPU、GPU、DSP、媒体和连接能力组织成移动计算平台。2011—2012 年的 Snapdragon S4 MSM8960 是一个关键实例：官方白皮书披露 Krait CPU、Adreno GPU、Hexagon DSP、System Fabric、L2 和内存子系统；后续官方说明披露 LTE 基带与应用处理器集成。[P01][P02][E02]

**能支持的判断：** 通信、计算与数据路径已经需要一起设计；集成可以减少某些芯片间边界，但不能只看“集成”两个字就推导续航收益。

**不能支持的判断：** 不能把 MSM8960 的续航变化单独归因于 LTE 基带集成，因为同一时期还涉及 28nm 制程、CDRX 等机制。早期样本不足以概括所有手机 SoC。

### 阶段二：2013—2016｜异构 CPU、专用媒体流水线与低功耗常驻路径

**阶段问题：** 峰值交互、待机、连续传感、摄影与视频对响应速度和能耗的要求不同。让所有任务一直运行在高性能 CPU 上并非唯一或必然高效的方案。

**结构响应。**

- Arm big.LITTLE 与后续 HMP 将不同 CPU 核与软件调度组合，试图覆盖不同性能/功耗工作点。[S01][R05][R07]
- Apple A7 将 64 位 CPU、GPU 和 ISP 组合到 SoC；iPhone 5s 另有 M7 运动协处理器，Secure Enclave 则位于 A7 内。M7 是手机系统级协处理器，不应被画进 A7 裸片内部。[P03]
- Snapdragon 820 将 Kryo、Adreno、Hexagon 680 HVX、Sensor Core、Spectra ISP、音视频编解码和 Symphony 系统管理组合起来。[P04][P05]

**结构意义：** 固定功能 ISP/编解码器负责稳定、高吞吐的流水线；DSP/HVX 提供可编程视觉处理；低功耗岛承担部分常驻传感；CPU/GPU继续承担控制、通用计算与图形。

**代价与限制：** 多引擎增加调度、驱动、内存共享和数据转换复杂度。异构 CPU 的收益依赖操作系统调度、负载迁移和具体终端；厂商的节能示例不是跨产品独立对照。

### 阶段三：2017—2020｜专用神经单元与 5G 平台分化

**阶段问题：** 计算摄影、语音、人脸、翻译等 AI 任务要求实时执行；同时 5G 增加通信吞吐、频段与 RF 系统复杂度。

**结构响应。**

- Apple A11 Neural Engine 与华为 Kirin 970 NPU 是专用神经处理进入手机 SoC 的代表路线；Qualcomm 的 Hexagon 则展示 DSP、向量/张量处理与共享存储演进。[S05][S06][T01][R06]
- Snapdragon 865 平台搭配 X55 Modem-RF；官方材料把 865 应用处理器与 X55 Modem Module 分列。[E05][P06][P07]
- 同期 ISP、编解码、DSP 与 NPU 不是互相替代，而是按任务与软件能力分工。

**结构意义：** AI 专用化开始明确，但物理边界仍多样。外置/配套 Modem-RF 可能服务于产品平台选择；不能简单把它归为“落后”，也不能据此推导比集成基带更耗电。

**代价与限制：** NPU 对算子覆盖、模型精度、驱动与运行时有依赖；不支持或低效的算子可能分区到 CPU/GPU。专用加速器理论吞吐不能代表实际应用时延或电池能耗。

### 阶段四：2021—2024｜工作负载导向的跨引擎协同

**阶段问题：** 影像、视频、语音与本地 AI 越来越像一条跨多个引擎的实时任务链；游戏图形复杂度也在增加。性能不仅取决于单元本身，还取决于任务是否能在时限内完成，以及数据如何在单元间移动。

**结构响应。**

- Google Tensor 公开 TPU、ISP、CPU/GPU、Content Hub 与 System Cache，并解释特定影像/音视频功能的跨引擎执行。[P08][P09][V03][V04]
- Samsung Exynos 2200 将 Xclipse RDNA 2 GPU、NPU/DSP、ISP、媒体编解码、集成 5G 基带与安全能力共同披露；硬件光追功能存在并不代表所有游戏都使用或在热稳态下可持续。[P10]
- MediaTek Dimensity 9300 的全大核 CPU 配置构成传统大小核配方的反例，APU 同时面向 Transformer、INT4 与内存压缩优化。[S08][R08][E07]
- Qualcomm Snapdragon 8 Elite 公布 Oryon CPU、分片式 GPU、Hexagon NPU 与 ISP 协作方向；这属于平台结构/厂商披露，不能直接当作独立因果测量。[S10][V05]

**结构意义：** 不能把“异构化”理解成每一类功能只属于一个单元。CPU/GPU/NPU/DSP/ISP 的能力有重叠，实际执行取决于工作负载、数据类型、驱动、软件入口和功耗状态。

### 阶段五：2025—2026｜数据管理、AI 能力分布化与持续热预算

**阶段问题：** 本地生成式 AI、长上下文、复杂图形、多摄/高帧率视频等任务提高了对模型状态、内存带宽、缓存容量、持续算力和终端散热的要求。多个引擎同时工作时还会争用共享资源。

**结构响应。**

- MediaTek Dimensity 9500 公开披露 CPU/GPU/NPU 动态共享数据缓存、SLC 管理、UFS、NPU 辅助 ISP/追焦及图形能力。[E08][P11][P12][V06]
- Qualcomm 2025 平台资料披露 HPM、Tile Memory Heap、Hexagon Direct Link、常驻处理、ISP/Modem-RF 与安全能力；2026 年 Hexagon 资料进一步提出 Element Accelerator、更大的 NPU 共享存储及低比特/模型加载支持。[E09][V13]
- Arm CSS for Mobile 2 将 CPU SME2、GPU 神经加速、系统互连/QoS 与软件支持一起作为 IP 平台发布。[E10][V14]
- Apple A20 Pro 产品披露 CPU/GPU/Neural Engine、内存带宽和终端封装/均热路径同时变化。[E11][P13]

**结构意义：** “有多少 TOPS”不足以解释本地 AI 的真实可用性；还要看模型加载、首 token、持续 token/s、内存容量/带宽、跨引擎执行、功耗和温度。同理，游戏持续表现要把 GPU、CPU 提交、显示合成、驱动和终端散热一起看。

**严格边界：** Arm CSS 是 IP/平台发布，不意味着所有 2027 年手机会采用。Apple 的整机持续性能变化同时涉及芯片、内存和散热，不能将全部收益归因于 CPU/GPU 微架构。Qualcomm/MediaTek 的共享存储收益也仍需要同口径独立验证。

### 3.1 历史阶段的总变化

| 变化轴 | 早期主要问题 | 近年新增压力 | 可归纳的趋势 | 不应写成的过度结论 |
|---|---|---|---|---|
| 计算职责 | 通用应用与图形 | 本地生成、实时视觉、矩阵计算 | 专用单元与通用计算并进 | 所有 AI 都迁到 NPU |
| 数据路径 | 芯片间/外存带宽 | 多引擎共享、模型状态、图形与 AI 争用 | 数据局部性与 QoS 更值得研究 | 共享缓存是所有任务第一瓶颈 |
| 低功耗执行 | 传感与音频常驻 | 常驻感知、轻量 AI、无线状态管理 | 按任务活跃度选择执行域 | 微型 NPU 必然比其他方案省电 |
| 通信边界 | LTE 集成与系统功耗 | 5G 多频段、SA/NSA、RF/天线/协议状态 | 集成与配套方案并存 | SoC 集成度必然单向增加 |
| 图形/媒体 | 固定流水线与基础 GPU | 光追、神经图形、高刷和长时游戏 | 固定功能、GPU 与软件路径协作 | 功能支持等于可持续体验 |
| 物理实现 | 面积、制程与电池 | 内存带宽、封装、供电、均热和持续功率 | 芯片与终端系统共同决定结果 | 整机提升都来自微架构 |

## 4. 模块级演进：机制、收益、代价与边界

### 4.1 CPU：从通用控制到更丰富的异构与矩阵能力

**职责。** CPU 仍负责操作系统、应用逻辑、控制流、分支密集任务、任务编排，以及其他加速器不支持或不适合执行的工作。CPU 并未因为 NPU 出现而退出 AI 路径。

**结构变化。** big.LITTLE/HMP 体现了不同 CPU 核对不同工作点的取舍；Dimensity 9300 的全大核说明高性能核路线也可能有产品价值；Arm SME2 等矩阵扩展则让 CPU 在特定 AI/矩阵任务上承担更多工作。[S01][R05][R07][E07][E10][V14]

**收益条件。** 任务足够并行或可由更强核心高效完成，且编译器/运行时能利用新指令；调度与电源管理能匹配负载。

**代价与未知。** 大核心面积与峰值功耗、轻载效率、迁移开销、软件支持和热预算相互影响。全大核不代表所有轻载和持续负载都优于大小核；CPU 矩阵扩展不等于它会在所有模型上胜过 NPU。

**评估建议。** 看低/中/高负载的性能-功耗曲线、单线程与多线程尾延迟、任务迁移、温控前后性能，以及真实编译器生成的指令与运行时选择。

### 4.2 GPU：图形吞吐、数据局部性和持续帧时序

**职责。** GPU 处理图形流水线和并行计算；现代移动 GPU 还可能支持硬件光追或神经相关计算。tile-based rendering、帧缓冲压缩和数据复用可减少部分外存流量。[S03][R04][G01]

**收益条件。** 真实游戏/应用使用对应功能；驱动、图形 API、资源格式与内容引擎匹配；访存和同步没有成为更大的瓶颈。

**代价与未知。** 光追、神经图形、高分辨率和高刷新率增加计算、带宽与热负担。峰值分数可能很好，但在长时负载中因温控、功率预算或系统策略而变化。图形 API 路径、帧同步、显示合成和限帧也会改变设备表现。[G02–G09]

**评估建议。** 同时记录 CPU/GPU frame time、present 间隔、p95/p99 帧时间、稳态 FPS、分辨率/画质、GPU/整机功耗与温度；短时跑分不能替代 20 分钟以上的持续曲线。

### 4.3 DSP、NPU 与 CPU/GPU 上的 AI 能力：不是单一路线替代

**职责。** DSP 擅长特定信号处理和可编程向量工作；NPU/张量单元针对矩阵/神经网络运算；CPU/GPU 仍可处理部分 AI 工作，尤其当任务小、控制复杂、算子不受支持或数据已经驻留于相应执行域时。

**结构变化。** A11/Kirin 970 代表专用神经单元进入手机；Qualcomm Hexagon 体现 DSP、向量、张量和共享存储的融合；2025—2026 的公开路线同时增加 CPU 矩阵、GPU 神经能力与 NPU 优化。[S05][S06][T01][V10][E10][V13]

**真正的瓶颈可能在哪里。** 模型装载、权重/状态读写、算子支持、量化误差、内存拷贝、驱动编译、任务分区、fallback 和热稳态都可能限制端到端结果。TOPS 仅描述某类峰值运算能力，不等于模型任务时延或能耗。

**软件可达性。** Android NNAPI 文档描述模型可能被分区，某些驱动执行失败可回退 CPU；memory domains 可帮助减少部分不必要拷贝。但 NNAPI 已弃用，不能把旧 API 文档当作 2026 所有手机唯一执行路径，也不能仅据 API 行为认定某款手机发生了 fallback。[V11][V12]

**评估建议。** 固定模型、数据集、精度和质量门槛；记录首 token、持续 token/s、每任务能量、模型加载时间、内存占用、执行分区与回退。优先比较同一版本基准的完整设备结果，不用不同模型的 TOPS 做跨芯片排名。[M03]

### 4.4 ISP、视频编解码与显示：固定流水线和可编程处理协同

**职责。** ISP 对像素流水线和实时影像预处理有专门能力；视频编解码器负责高吞吐格式处理；DSP/NPU 可以执行部分语义、追焦或视频算法；显示与图形合成将结果及时呈现。

**结构变化。** Snapdragon 820 公开披露双 ISP、HVX、Sensor Core 和编解码；Google Tensor 把 Live HDR+ 等处理放进 ISP 路径，并披露 TPU 参与部分音视频任务；后续平台公开 ISP 与 NPU 更紧密的功能协作。[P04][P08][P09][V01–V06]

**关键约束。** 视频是连续流，必须在帧期限内处理每帧并同时完成预览、缓冲、编码/显示；端侧 AI 则有模型加载、预处理、推理与输出等阶段。二者都涉及数据移动，但 QoS 不同。

**量纲示例。** 3840×2160、60 帧/秒、每像素 10 bit 的纯单次像素流约为 0.622 GB/s（十进制）。这只是未计多次读写、行间隙、多摄、缓冲和编码的输入量纲下界，不是任何 SoC 的实测 DRAM 带宽。

**边界。** 相机 HAL 和 buffer 接口证明了软件/硬件交互边界，不证明某芯片数据必经某个缓存或 DRAM 路径。[V07][V08]

### 4.5 Modem-RF、天线与无线低功耗：独立于共享缓存的系统维度

**职责。** Modem/baseband 处理协议与基带任务；RF 收发器、射频前端和天线共同决定无线链路表现。AP、Modem、RF 与天线可能位于不同芯片/模块/终端位置，具体产品需要逐一核实。

**结构变化。** S4/MSM8960 集成 LTE；Snapdragon 865 搭配 X55 Modem-RF；Exynos 2200 又公开披露集成 5G 基带。[E02][E05][P07][P10][N04–N06]

**低功耗机制。** 3GPP NR 连接态 DRX 允许配置接收周期；BWP、WUS、SCell 休眠等技术也被厂商资料用于描述无线节能策略。[N01–N03] 这些机制的实际效果取决于网络配置、信号、业务模式、唤醒/重传和手机实现。

**独立测量提醒。** X01 的 5G 能耗百分比仅从摘要/机构元数据核到，X01/X02 属同团队来源链；X04 测量 TRP/TIS，单位 dB；X10 测上行占空比。这些数据不能混作手机电池瓦数或芯片能效排名。X05 的对象是笔记本加外置 CPE，不是手机 Modem。[X01–X06][X10]

**评估建议。** 固定手机、频段、SA/NSA、RSRP/SINR、网络负载、上下行比例、DRX 配置、屏幕/Wi-Fi 状态和环境，区分 Modem rail、主板与整机功耗；没有同口径数据时只报告机制和条件，不报告普遍的 4G/5G 节能百分比。

### 4.6 缓存、SLC、DRAM、UFS 与互连：从“有缓存”转向任务级数据治理

**结构信号。** Snapdragon 820 已有帧缓冲/带宽压缩；GPU tile-based rendering 试图在片内复用数据；Dimensity 9500 公开披露 CPU/GPU/NPU 动态共享数据缓存与 SLC 管理；Qualcomm 公开 GPU Tile Memory Heap、NPU 共享存储与 Direct Link；Arm CSS for Mobile 2 把互连、QoS 和软件支持作为平台的一部分。[P04][G01][E08][E09][V13][V14]

**为什么可能有价值。** 当任务在多个引擎之间传递中间数据时，减少不必要的 DRAM 往返、转换和复制可能降低延迟与能耗，并缓解带宽压力。

**为什么不能泛化。** 不同任务的数据访问形态不同；共享缓存可能引入容量争用、一致性和 QoS 管理成本。增加缓存面积也有代价；更高 DRAM 带宽、模型量化/压缩、软件融合、任务重排或云端卸载可能是替代路线。当前没有公开的逐任务命中率、带宽流量和能耗 A/B 证明共享缓存对四类任务都居首。

**当前判断。** [OBSERVATION] 数据局部性是 AI、视频和部分图形负载值得检验的机制方向；[UNKNOWN] 各产品真实 NoC 拓扑、跨引擎路径、命中率、每域功耗与收益比例大多未公开。

### 4.7 低功耗岛、常驻感知与安全

**低功耗常驻。** iPhone 5s 的 M7、Snapdragon 820 Sensor Core、后续 Sensing Hub/微型 NPU 等例子说明常驻传感和轻量任务可有不同于主 CPU/GPU 的执行路径。[P03][P04][E09] 但 M7 是手机系统级协处理器，不能等同于 SoC 内部低功耗岛。

**安全边界。** A7 Secure Enclave、Google Tensor security core 与 Titan M2、Exynos embedded Secure Element、Qualcomm 的 TEE/SPU/模型保护等公开资料说明安全已成为系统分工的一部分。[P03][P08][P10][E09] 模块名称相似不代表相同威胁模型或安全强度；公开产品页面不支持跨厂商安全排名。

**取舍。** 常驻功能会带来静态功耗、隐私和攻击面问题；本地模型也增加数据在多个执行单元之间流动的范围。未来设计需同时考虑低功耗、权限和安全隔离，而非只看运算吞吐。

### 4.8 制程、频率、内存、封装与散热：不能从整机结果直接推微架构

芯片性能和能耗受多因素共同影响：制程与电压/频率、核心数量和面积、缓存/DRAM 容量与带宽、编译器/驱动、任务调度、封装、供电、机身热阻、均热设计、屏幕和环境温度。Apple A20 Pro 的公开描述同时涉及处理引擎、内存带宽和封装/均热路径，恰好说明整机收益并非单一微架构变量。[E11][P13]

**归因规则：** 若没有同工艺、同工作负载、同软件和可控温度的 A/B，不能将跨代提升精确分配给某个 CPU/GPU/NPU 微架构。即使产品用同一 SoC，不同手机的持续表现也会受固件、功率限制、散热和屏幕/分辨率影响。[X07–X09]

## 6. 四类负载：同一 SoC，四种不同的 QoS 与瓶颈

### 6.1 持续 4K 视频：硬帧期限与流水线

**任务链。** 传感器 → ISP/RAW 预处理 → 可能的 DSP/NPU 语义/影像处理 → 编码器/预览与显示缓冲 → 存储/分享。相机 HAL 与 buffer 接口把应用请求接到驱动/硬件，但不暴露所有芯片内部数据路线。[V01–V08]

**主要 QoS：** 每帧截止期、持续录制、画质、音视频同步、热稳定。

**候选瓶颈：** 连续像素流、多个处理阶段的缓冲/读写、DRAM 带宽、ISP 与 AI 的协同、编码和热稳态。

**替代路线：** 固定功能流水线、压缩、算法简化、缓存/片内复用、提高 DRAM 带宽、调整帧率/分辨率。

**判断：** [OBSERVATION] 公开结构从 ISP/编解码扩展到 DSP/NPU 和跨引擎协作；[HYPOTHESIS] 数据移动可能是某些高帧率/多摄场景的重要成本。缺少逐帧流量和能耗测量时，不宣称其为所有视频负载首要瓶颈。

### 6.2 端侧 AI / 多模态推理：从 TOPS 转向任务完成成本

**任务链。** 模型从 UFS 加载到可用内存 → 预处理与编译/分区 → CPU/GPU/NPU 执行 → 中间状态读写 → 输出到应用/显示/音频。不同阶段对带宽、算子支持和时延的要求不同。[V09–V14]

**主要 QoS：** 首 token 延迟、持续 token/s、任务总时延、模型质量、内存占用和每任务能耗。

**候选瓶颈：** 模型/权重加载、内存容量与带宽、算子支持、精度与质量、跨单元拷贝、运行时 fallback、热稳态。

**替代路线：** 更大 NPU、CPU SME2/矩阵能力、GPU 神经能力、量化/压缩、算子融合、软件调度、云端卸载或更小模型。

**判断：** [OBSERVATION] AI 设计重心已从新增 NPU 扩展到精度、共享存储、软件路径和多引擎协同；[UNKNOWN] 哪种路线在目标手机/模型上能耗最低，必须由同版本、同质量门槛、同场景测量回答。

### 6.3 蜂窝通信：网络状态和 RF 不是通用缓存问题

**任务链。** 应用/协议 → Android Connectivity/Telephony 与 Radio HAL → Modem/baseband → RF 收发器/射频前端/天线 → 网络；控制路径受 RRC 状态、DRX、带宽部分、唤醒和重传等影响。[N01–N08]

**主要 QoS：** 时延、可靠性、吞吐、连接保持和电池寿命。

**候选瓶颈：** 弱信号、无线环境、上/下行负载、接收机活跃时间、RF 功率、重传和协议状态。

**替代路线：** DRX/WUS/BWP/SCell 休眠、网络调度、Modem/RF 设计、天线/RF 优化、应用流量策略。

**证据限制。** X01 摘要中的 LTE/NSA/SA 百分比未核实完整设备与实验边界；X02 为同团队研究链。X03 是 Pixel 7A 的手机子系统测量方向；X04 是 OTA 射频指标，X10 是上行占空比，二者都不是电池功率。X05 不是手机 Modem 实测。[X01–X06][X10]

**判断：** 无线状态与 RF/网络条件是独立的系统能效维度。没有固定终端和网络条件的对照，不给普遍的“5G 比 4G 多耗电 X%”结论。

### 6.4 持续游戏：帧时间、功率策略与热稳态

**任务链。** CPU 游戏逻辑与提交 → GLES/Vulkan → GPU 渲染与缓存/内存 → BufferQueue/SurfaceFlinger/HWC → 显示；Android Swappy、ADPF、限帧和动态分辨率会改变实际工作量。[G01–G09]

**主要 QoS：** 稳态帧率、p95/p99 帧时间、帧间隔一致性、画质、触控响应和温度。

**时间预算。** 60 fps 对应约 16.67 ms/帧，120 fps 约 8.33 ms/帧。它们是帧时序预算，不代表 GPU 可独占全部时间。

**候选瓶颈：** shader/图形计算、内存带宽、CPU 提交、同步、显示合成、功率上限和热反馈。

**替代路线：** 帧 pacing、限帧、分辨率/画质缩放、资源优化、tile/压缩、驱动与调度优化、终端散热。

**独立观察。** 同 Dimensity 9500 的 OPPO Find X9 与 vivo X300 报告的 Wild Life Extreme Stress Test 稳定性为 74.3% 和 46.7%。稳定性百分比不等于 FPS、绝对稳态得分或能效；两台手机在软件、散热和功率策略上并非严格控制变量。[X07][X08][X09]

**判断：** 相同 SoC 不能保证相同的持续游戏体验，但现有数据不足以判断差异由哪一个因素造成。需要逐 loop 分数/帧率、温度、GPU 频率、设备功耗和软件版本轨迹。

### 6.5 四任务并排比较

| 任务 | QoS 核心 | 关键执行域 | 首先应测什么 | 常见误判 |
|---|---|---|---|---|
| 4K 视频 | 帧期限、持续录制/画质 | ISP、编解码、DSP/NPU、DRAM、显示 | 丢帧、帧时延、每秒/每任务能耗、温度 | 把共享缓存当已证实首要瓶颈 |
| 端侧 AI | 首 token、持续 token/s、质量 | CPU/GPU/NPU、UFS/DRAM、运行时 | 端到端时延、能耗、质量、执行分区 | 用 TOPS 代替真实模型效果 |
| 蜂窝通信 | 时延、可靠性、连接与电池 | Modem、RF、天线、协议状态、AP | 固定网络条件下每任务能量与吞吐/重传 | 把射频 dB 或 duty cycle 当电池瓦数 |
| 持续游戏 | 帧时间尾部、稳态帧率与热 | CPU、GPU、缓存/DRAM、显示、OS | p95/p99 帧时间、稳态 FPS、功耗与温度 | 用单次峰值分数推断长时体验 |

**跨任务结论：**共同规律是 QoS 目标推动计算分工、数据路径、软件可达性和功耗管理协同；不同任务的首要瓶颈可能完全不同。因此应比较端到端任务结果，而不是先假设某一个共享硬件资源主导全部场景。

## 7. 如何区分微架构收益与其他因素

### 7.1 归因检查矩阵

| 变量层 | 典型因素 | 如果未控制，可能造成的误判 |
|---|---|---|
| 微架构 | 执行宽度/调度、缓存层级、tile、专用矩阵/神经单元、数据路径 | 将系统收益错误归给某个执行单元 |
| 工艺/电气 | 制程、晶体管库、电压/频率、泄漏、供电 | 把工艺和工作点改善说成纯 IPC/架构提升 |
| 容量/资源 | 核数、缓存容量、DRAM 通道/带宽、内存容量、频率 | 把资源增加与机制变化混为一谈 |
| 软件 | 编译器、驱动、OS、运行时、API、模型/图形优化 | 把软件升级归因于硬件 |
| 物理终端 | 封装、散热、均热、机身厚度、供电和电池 | 把整机持续性能差异归因裸片 |
| 工作负载/环境 | 游戏版本、模型、分辨率、亮度、网络、室温、信号强度 | 形成不可比的基准或功耗结论 |

### 7.2 因果归因的最低要求

若要宣称“机制 A 带来 X% 收益”，至少应有：

1. 明确 A 的启用/关闭或可比较实现；
2. 固定工作负载、软件版本、质量、功率边界和环境；
3. 给出基线与目标指标、持续时间、重复次数与波动；
4. 记录功耗/热/资源开销，而不仅是性能；
5. 检查替代解释，如制程、频率、容量和软件变化；
6. 说明结论适用到哪些设备/任务，而非泛化整个行业。

当前公开产品材料大多满足“结构存在/厂商披露”，不满足以上全部因果要求。故本报告不为各模块分配精确性能贡献百分比。

## 8. 2027—2028：有条件的趋势判断

置信度分开看：**方向置信度**不等于**收益幅度置信度**。方向有多条公开信号支撑时，可以判断“值得关注”；但没有任务级实测时，收益幅度仍低置信。

| 方向 | 置信度 | 已有前置信号 | 可能的系统收益 | 替代解释/证伪条件 |
|---|---|---|---|---|
| **多域 AI 执行：CPU/GPU/NPU 分工继续变化** | 方向：高；收益幅度：低 | CPU SME2、GPU 神经单元、NPU 共享存储、低比特与模型加载优化已被公开。[E08–E10][V13][V14] | 按任务阶段选择合适执行域，兼顾小任务延迟与大模型吞吐 | 如果软件接口、算子支持和调度开销阻止跨域执行，或单一 NPU 始终更优，实际分布可能较窄 |
| **模型数据与内存治理持续重要** | 方向：中高；是否为首要瓶颈：低 | 动态共享缓存/SLC、Tile Memory Heap、低精度/压缩、UFS/DRAM路径持续出现在公开材料中。[E08][E09][V06][V13] | 减少不必要数据移动、提升局部性和共享资源可预测性 | 更大 DRAM 带宽、量化/压缩、模型缩小、软件融合或云卸载可能更有效；若任务测量没有改善，应下调缓存路线 |
| **持续功率和热反馈成为更重要的系统指标** | 方向：中高；具体因果：低 | 2026 产品披露同时涉及内存带宽、封装和均热；相同 SoC 设备压力稳定性存在差异。[E11][X07–X09] | 提高长期性能可预测性，降低突发降频与体验波动 | 如果差异主要来自驱动/软件功率策略，新增硬件热设计并非唯一解 |
| **无线协议状态与 RF 继续是独立节能方向** | 方向：中高；收益幅度：低 | DRX、BWP、WUS、SCell 休眠与网络自适应已有标准/厂商披露。[N01–N03] | 降低无数据时的监听与连接维持成本，改善单位数据能耗 | 网络覆盖、调度和业务模式可能主导实际结果；需固定条件设备测量 |
| **ISP/媒体与神经处理的协同深化** | 方向：中高；跨产品收益：低 | ISP/NPU 协同追焦、AI ISP/Direct Link、视频实时 ML 已有产品披露。[P08][P09][V05][V06] | 在固定帧期限内融合传统像素处理和语义任务 | 更高带宽、独立流水线或软件算法可能更合适；没有逐帧流量和能耗数据不选路线赢家 |
| **常驻感知与安全域保持重要** | 方向：中；实际部署范围：低 | M7、Sensor Core、Sensing Hub、微型 NPU、安全核心与 TEE/SE 等跨代实例。[P03][P04][E09][P10] | 在主 CPU/GPU 不活跃时承担轻量任务，并隔离敏感数据 | 静态功耗、隐私/权限、攻击面和生态适配会限制常驻功能 |

### 8.1 不作出的预测

- 不预测 2027—2028 年某款 SoC 的确切核心数、缓存容量、TOPS、频率或上市时间。
- 不预测某一家厂商必胜；不同产品定位、软件生态、终端散热和供应链会改变取舍。
- 不把 Arm IP 发布等同所有厂商量产采用。
- 不把厂商的“提升 X%”作为跨厂商、跨应用通用收益。
- 不把“Agentic AI”当作自动改变芯片架构的原因；只有当长上下文、工具调用、常驻执行或多模态任务改变了真实工作负载和 QoS，才构成可检验的架构需求。

## 9. 对 CPU 优化与系统研究团队的启示

本节是基于公开结构信号提出的研究建议，不代表已经在目标产品上测得收益。

### P0｜建立任务级测量闭环（优先级最高）

- 以视频、AI、无线和持续游戏四类代表任务建立可重复的端到端基线。
- 对每次测试记录设备/SoC、OS/驱动、编译器/运行时、模型或游戏版本、功耗边界、温度与时长。
- 先测任务结果与瓶颈，再决定是否需要更大缓存、更多计算单元或不同调度；不要从架构趋势直接跳到设计方案。

### P1｜优先验证软件可达性和 CPU 的系统作用

- 检查 CPU 是否承担了不适合专用引擎的控制、预处理、fallback、数据转换和同步开销。
- 对 CPU 矩阵/向量扩展，核实编译器是否生成目标指令、运行时是否实际调用，以及端到端时延/能耗是否改善。
- 记录 CPU/GPU/NPU 之间的拷贝、同步、排队和任务切换开销。软件分区不合理时，增加硬件峰值吞吐可能无法改善整体任务。

### P1｜将数据局部性作为可证伪 PoC，而非预设答案

- 选取一个多引擎任务，测量 DRAM 流量、缓存行为、带宽争用和每任务能量。
- 比较缓存/复用、量化/压缩、软件融合、较高内存带宽等竞争方案。
- 只有当测量显示数据移动限制目标任务，才把共享缓存/片内直连升级为重点；如果收益不稳定或被软件/热因素覆盖，应降级。

### P2｜跟踪无线与终端热预算

- 对通信测试分开固定网络、RF 条件、DRX 状态和整机功耗范围。
- 对游戏/视频记录长期性能曲线与热状态，不只保留首轮峰值。
- 若团队无法访问 Modem/RF rail 或机内热遥测，应明确数据边界，不能用整机数据冒充单元功耗。

### 暂不支持的路线

- 仅以 TOPS、FLOPS、峰值频率或单次跑分决定架构优先级。
- 把“共享缓存是四类负载共同瓶颈”当作已证实前提。
- 用未经控制的跨手机对比推断某家 CPU/GPU/NPU 微架构优越。
- 将厂商发布的效率百分比直接转化为项目 KPI 或量产收益。

## 10. 五个最终研究问题：逐项回答与验收状态

| 问题 | 结论 | 状态 |
|---|---|---|
| **Q1. 2007—2026 年手机 SoC 经历哪些阶段与转折？** | 五阶段主线可解释连接集成、异构/常驻、专用 AI/5G、跨引擎协同和数据/热预算等代表变化。阶段为分析分期，早期和中低端样本较少。 | **有边界的定性回答** |
| **Q2. 各模块如何分工、收益与代价是什么？** | CPU/GPU/DSP/NPU/ISP/媒体/Modem/RF/内存/安全/软件的职责与四类 QoS 可分层说明；收益多不能从产品发布材料中单独量化。 | **机制可回答，因果量化不足** |
| **Q3. 哪些是微架构，哪些来自工艺、软件、封装、散热或环境？** | 归因框架与必要变量已建立；公开资料多数没有严格控制变量，无法计算单因素贡献。 | **分类规则可回答，精确贡献未知** |
| **Q4. 厂商是否有不同解法？** | 有：大小核与全大核、集成与配套 Modem-RF、专用 NPU 与 CPU/GPU 矩阵/神经能力、固定流水线与 AI 协同等。路线受产品目标与软件生态影响，不能排出无条件赢家。 | **代表路线可回答，不做性能排名** |
| **Q5. 2027—2028 可能演进什么？** | 多域 AI 执行、数据/内存治理、无线状态节能、持续热反馈、媒体与 AI 协同、常驻感知值得观察。每条方向需同时保留替代路线和证伪条件。 | **条件性前瞻，不预测具体产品规格** |

### 10.1 仍需保留的未知项

1. 大多数 SoC 的 NoC/一致性互连完整拓扑、实际缓存命中率、跨引擎逐任务数据流未公开。
2. 各功耗域在目标应用中的瞬时功耗与能量占比通常不可得。
3. 缺乏跨厂商同工艺、同软件、同模型/游戏、同终端热条件的受控 A/B。
4. 无线能耗论文中部分结果只核到摘要；研究对象、网络条件和计量边界不足以支持普遍化结论。
5. 同 SoC 不同手机的持续游戏差异尚未通过逐 loop 绝对成绩、温度、功率和软件轨迹完成因果拆分。
6. 2027—2028 的 IP/平台是否量产采用、软件栈何时成熟、实际收益幅度仍未知。

这些未知项是公开研究边界，不是研究失败，也不能用推测补齐。

## 13. 最终结论

截至 2026-10-20，公开证据支持把手机 SoC 演进理解为**负载驱动的异构分工、跨引擎数据/控制协同，以及芯片与终端电热预算的共同设计**。从早期 LTE/AP 集成、常驻感知与 ISP/DSP 分工，到专用神经单元、跨引擎媒体/AI，再到 CPU/GPU/NPU 多域能力、共享数据管理和封装/散热协同，这条主线有代表性官方结构证据支撑。

但“系统协同越来越重要”不等于已找到所有任务的单一瓶颈。AI 的首 token 与持续 token/s、视频帧期限、蜂窝协议状态、游戏帧时序和热稳态，必须用不同 QoS 与端到端测量来验证。共享缓存是部分任务的候选机制，而非普遍答案；基带集成不是单调趋势；峰值算力不能替代真实任务结果。

因此，最稳妥的 2027—2028 预测是：多域 AI 执行、数据与内存治理、无线低功耗状态、媒体/AI 协同和持续热反馈仍值得关注。方向置信度高于收益幅度置信度。下一步应由技术专家评审本报告中的关键机制、反例和未知项；若需要将某方向升级为工程投资或架构决策，必须补充固定负载、基线、功耗边界与热条件下的可证伪实验。
